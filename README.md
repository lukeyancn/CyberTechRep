# CyberTechRep 课堂信息分发

把班级 QQ 群里的消息和文件接进 ClassIsland：自动分出通知和作业、判断学科、按学科归档文件，并显示在桌面悬浮窗上。

| 项 | 值 |
| --- | --- |
| 当前版本 | `2.2.0.0`（`src/CyberTechRep.Plugin/manifest.yml` 与 `CyberTechRep.Plugin.csproj` 同步） |
| 作者 | Chenxuan Yan |
| 仓库 | <https://github.com/lukeyancn/CyberTechRep> |
| 插件 ID | `classisland.classing`（宿主 API 版本 `2.0.0.0`） |
| 运行平台 | Windows（插件入口声明 `SupportedOSPlatform("windows")`） |

**它解决什么问题**：班级群里老师发的通知、作业、课件文件混在一起，学生要翻聊天记录。这个插件接住这些消息，把通知和作业分开、判断作业属于哪个学科，在桌面上用悬浮窗常驻显示，并把文件按「学科 / 日期」自动存好。

阅读导航：

- 想直接装上用：第 3、4、5、6、7 章。
- 想看代码：第 8、9 章。
- 想评估是否采用：第 2、7、10、11 章。

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows（插件入口与宿主都是 Windows 桌面程序） |
| 宿主 | ClassIsland 2.x（插件清单 `apiVersion: 2.0.0.0`；本仓库开发环境随附的宿主为 2.1.0.1） |
| 运行时 | .NET 8 桌面运行时（宿主 `ClassIsland.Desktop.runtimeconfig.json` 依赖 `Microsoft.NETCore.App 8.0.0` 与 `Microsoft.WindowsDesktop.App 8.0.0`） |
| 插件包 | `.cipx`（ClassIsland 插件包格式），由 Release 构建产出 |
| 消息源（二选一） | ① QQ 官方机器人开放平台（默认）；② 自备 NapCat（OneBot 11，可选替代） |

两种消息源的差别：

| | QQ 官方机器人 | NapCat（OneBot 11） |
| --- | --- | --- |
| 前置条件 | 在 q.qq.com 注册机器人，取得 AppID / AppSecret，把机器人接入群 | 自备 NapCat 本体（插件不内置），本机可用的 QQ 账号 |
| 群标识 | 群 OpenID（字符串） | 纯数字群号 |
| 历史补拉 | 平台不提供，插件不会补历史消息 | 支持（`get_group_msg_history`，插件默认在连接后核对一次） |
| 撤回事件 | 平台不下发 | 会下发，但非 API 撤回（如在手机 QQ 上撤回）有已知缺陷不上报，详见第 10 章 |
| 附加能力 | 无 | 插件可一键启动 NapCat、读日志、打开 WebUI |

## 2. 功能总览

| 功能 | 说明 |
| --- | --- |
| 消息接管 | 两种接入方式都支持：QQ 官方机器人 WebSocket 网关，或 NapCat 正向 / 反向 WebSocket。按群白名单过滤，按消息 id 幂等去重（重启不重复落档） |
| 通知 / 作业自动分类 | 关键词计数判定（词表可编辑）：命中多的一侧胜；两侧相同或都没命中且文本非空时归为**通知**（不丢消息）；纯图片 / 纯文件等无文本消息不产生空通知条目，走文件管道 |
| 学科识别 | 三级链：① 学科关键词（`subjects.json`，可编辑）→ ② AI（可选，云端 API）→ ③ 人工确认队列。默认「成员绑定优先」：先看发消息的人有没有绑定学科，没绑定再走关键词，都认不出来时弹出选择窗 |
| 通知悬浮窗 | 未读 / 已读两个视图（未读不限时间，已读只列当天）；每条可标记已读 / 未读、可「转为作业」；正文可选中复制 |
| 作业悬浮窗 | 按学科分组显示**当天**作业，每学科一份连续文档；点文字进入编辑（停顿后自动保存）；可「转为通知」、可清空本学科当天文档；底部「整理并发送」把当天清单发到目标群 |
| 学科文件悬浮窗 | 按日期倒序列出该学科全部已归档文件，大图标 / 详细列表两种视图，图片显示缩略图；点文件用系统默认程序打开 |
| 学科圆圈启动器 | 常驻小窗，一个学科一个圆圈；点击打开 / 切换学科文件悬浮窗，右键可上移 / 下移；学科有新归档文件时显示小红点（会话内有效） |
| 图片悬浮窗 | 群里发来的图片自动（可关）加入悬浮窗，竖向排列、多图累积，最多保留 20 张，标题栏「打开」用系统查看器打开当前图片 |
| 未绑定学科选择窗 | 消息需要学科但发送者没绑定时弹出，按到达顺序逐条处理（可「跳过（暂不绑定）」），点选后写回绑定并修正该消息的学科与文件归档 |
| 文件自动下载与归档 | 下载到「下载文件 / 学科 / 日期」；MD5 去重；可设并发、限速、单文件上限、磁盘占用上限与清理策略；失败自动重试 |
| 通知 ↔ 作业互转 | 通知可转作业、作业（单条与整篇文档）可转通知，学科与来源随之继承；覆盖记录持久化，重投 / 续传不回摆 |
| 作业清单「整理并发送」 | 确认窗内可勾选「常态化作业」（按学科配置的固定作业项）、可直接编辑待发文本、可自动补序号，点「发送」才写档并发送到目标群 |
| 上课自动弹出 | 进入上课时自动弹出 / 切换当前学科的文件悬浮窗（默认关闭）；支持延时：正数上课后推迟 N 秒、负数上课前提前 N 秒 |
| AI 识别增强（可选） | 四种用途各自选择「关闭 / 唯一识别 / 后补识别」；支持 OpenAI 兼容接口与 Anthropic 接口；不配置也能用（自动跳过 AI） |
| 消息记录导出与失败重试 | 「维护与排错」页可导出最近消息（JSONL，含分类 / 学科 / 文件结果，不含密钥）、查看连接状态与最近消息、手动重连、重放失败任务 |
| 拖放导入 | 把文件拖到学科圆圈或学科文件悬浮窗，可复制归档到该学科（与下载共用同一记录库） |

## 3. 安装与首次运行

1. 取得 `CyberTechRep.Plugin.cipx`（仓库 Release 附件，或本地 Release 构建产物 `src/CyberTechRep.Plugin/cipx/CyberTechRep.Plugin.cipx`）。
2. 打开 ClassIsland「应用设置 → 插件」页，把 `.cipx` 拖入即可安装（该页的安装入口支持选文件；插件包扩展名固定为 `.cipx`）。
3. 按该页提示点「重启以应用更改」，重启 ClassIsland。
4. 重启后插件会在「应用设置」里新增 **CyberTechRep** 分组，共 9 个设置页：连接、分类、CyberTechRep AI、词表编辑、常态化作业、悬浮窗、文件、维护、关于。

首次运行（`settings.json` 中 `FirstRunCompleted` 为 false）会自动弹出引导窗，共 9 步：

| 步骤 | 配什么 |
| --- | --- |
| 欢迎 | 插件做什么、接下来配哪些 |
| 连接方式 | 选 QQ 官方机器人或 NapCat，并填该模式必需的参数 |
| 接管哪些群 | 群白名单 |
| 作业清单发到哪 | 发送目标群与发送开关 |
| 通知、作业与学科 | 学科识别方式、选择窗开关、通知学科前缀 |
| 悬浮窗 | 六个窗口的初始显示组合 |
| 文件与保留 | 下载目录、通知 / 作业保留天数 |
| 日常怎么用 | 操作说明 |
| 完成 | 汇总「已配置 / 未配置 + 去哪补」 |

引导的每一步都可以「跳过这一步」，欢迎页的「跳过引导（稍后再配）」跳过整个引导；完成或跳过都会写入 `FirstRunCompleted`，不会重复弹出。想再看一遍：**设置 → CyberTechRep 维护 → 首次启动引导 → 重新打开引导**（已填过的连接信息会带入，不会被清空）。

## 4. 快速开始

### 4.1 路径 A：QQ 官方机器人（默认）

1. 在 q.qq.com 注册机器人，取得 **AppID** 与 **AppSecret**，按平台流程把机器人接入班级群。
2. 打开「设置 → CyberTechRep 连接」，确认「接入模式」为 **QQ 官方机器人（默认）**，填入 AppID 与 AppSecret（密钥加密后只存本机，界面不明文回显），保存。
3. 群白名单（见第 6 章「连接」表）先留空或填入目标群 **群 OpenID**；保存。
4. **验证**：在群里发一条消息 → 打开「设置 → CyberTechRep 维护 → 排错面板 → 刷新」。「最近消息」里出现这条消息即接通；同时可看面板顶部的连接状态。群 OpenID 也可以在这里从消息条目上读到，再填回白名单。

> 官方平台没有历史补拉接口，插件只能收到连接建立之后的新消息；主动消息（「整理并发送」）受平台频控，详见第 10 章。

### 4.2 路径 B：NapCat（OneBot 11）

前置：自己准备 NapCat 本体并安装（插件不内置）。官方 Shell 包（无头）不显示 QQ 界面；官方 Framework 包（有头）会启动带完整界面的 QQ。两种包请分开目录安装，不要共用配置和缓存。

1. 「设置 → CyberTechRep 连接 → 接入模式」选 **NapCat（OneBot 11）**。
2. 通信方式（二选一）：
   - **正向 WebSocket**：填「NapCat 正向 WebSocket 地址」（例如 `ws://127.0.0.1:3001`），对应 NapCat 侧的「WebSocket 服务器」配置。
   - **反向 WebSocket**：正向地址留空，「反向 WebSocket 监听端口」保持 `3001`（0 = 不启用），在 NapCat 的「WebSocket 客户端」里指向 `ws://127.0.0.1:3001`。
3. access token 可选：NapCat 配了 token 就在这里填同样的值（加密存储）；留空表示不校验。
4. 一键启动（可选，在「NapCat 一键启动」折叠区）：选运行形态（无头 / 有头）、填启动文件路径（无头填启动脚本如 `launcher-user.bat`；有头填有头包入口或官方 `QQ.exe`）、选登录方式（扫码，或填 QQ 号快速登录）、按需打开「启动后自动后台启动」「启动前结束正在运行的 QQ」「启动后打开 WebUI」。然后点「启动 NapCat」。
5. **验证**：「排错面板」的连接状态显示**已连接**才算接入成功（握手成功不算，插件要等到 NapCat 的生命周期 / 心跳事件）；NapCat 后台日志区有输出；群里发一条消息出现在「最近消息」里。填白名单时用**群号（纯数字）**。

> NapCat 以注入方式运行在 QQ 进程内，需要独占 QQ 实例，所以默认「启动前结束正在运行的 QQ」；QQ 已在运行且未结束就启动，NapCat 拿不到已登录会话（表现为只弹二维码、始终不接入）。

## 5. 日常使用

悬浮窗通用操作：标题栏拖动移动、右下角拖动缩放；标题栏「⋯」是快捷设置菜单（置顶 / 固定 / 鼠标穿透，与设置页等价，切换即时生效）；「×」只隐藏该窗口，想再显示到「设置 → CyberTechRep 悬浮窗」打开对应的「显示悬浮窗」。

**通知悬浮窗**：未读视图列出**全部未读**通知（不限时间），底部可切到「已读」（只列当天已读）。每条右侧有「已读 / 标记未读」与「转为作业」；正文可选中复制（右键有复制 / 全选菜单）。「转为作业」在通知已有学科时直接继承，无学科时会让你选一个。

**作业悬浮窗**：只显示**当天**的作业，按学科分组，每个学科一份连续文档。点文档文字进入编辑态，停顿或点开别处即保存（存档以你编辑后的文本为准，新消息以末尾追加方式并入，不会丢你的删改）。每学科下方有「转为通知」与清空（需再点一次确认，清空的是该学科当天文档）。底部「整理并发送」打开确认窗：可勾选常态化作业、可直接编辑待发文本、可重新生成清单，点「发送」才写档并发送。

**学科圆圈与红点**：圆圈栏常驻，点圆圈打开该学科的文件悬浮窗；右键圆圈可「上移 / 下移」调整顺序；学科有新归档文件时圆圈右上角出现红点，点开该学科后被清除（红点只在本次运行内有效）。

**学科文件悬浮窗**：默认隐藏，由圆圈点开；按日期倒序列出该学科**全部**已归档文件（不限当天），两种视图（大图标 / 详细列表），图片显示缩略图；点条目用系统默认程序打开。把文件拖到文件悬浮窗或圆圈上可导入归档（该窗口开了鼠标穿透时收不到拖放）。

**图片悬浮窗**：默认隐藏，收到图片且「收到图片自动展示」开启时自动弹出；竖向排列、最多 20 张（超出丢最旧），新图到达自动滚到可见位置；标题栏「打开」用系统默认看图工具打开当前视口中心最近的图片。

**上课自动弹出与延时**：在「悬浮窗 → 圆圈栏排列与文件悬浮窗联动」里打开「上课时自动弹出对应学科的文件悬浮窗」，并设延时：`0` 准点，正数上课后推迟 N 秒，负数上课前提前 N 秒。下课 / 放学 / 查不到当前课会收起联动打开的窗；你手动打开的窗不受影响。课中把文件发进群，当归档完成时也会立即补弹。

**未绑定学科选择窗**：发送者没绑定学科时弹出，显示发送者、群、消息摘要与待处理条数；点一个学科即完成绑定并按该学科归档（同时修正该消息的作业条目与文件归档）。点「跳过（暂不绑定）」只跳过这一条，后面的继续依次弹出。

**通知与作业互转**：互转时学科与来源会一起继承（通知界面不显示来源，来源只在作业侧展示）；正文里与新学科一致的「学科：」前缀会被去掉，来回转换不会累积前缀。

## 6. 关键设置项

以下默认值取自 `src/CyberTechRep.Shared/Models/SettingsModels.cs`，字段名与设置页控件逐项核对过。

### 6.1 CyberTechRep 连接

| 设置项 | 作用 | 默认值 | 什么时候改 |
| --- | --- | --- | --- |
| 接入模式 | 官方机器人 / NapCat | QQ 官方机器人 | 要换消息源时；切换后需到「维护 → 手动重连」或重启宿主才生效 |
| 机器人 AppID | 官方模式凭据 | 空 | 首次配置官方机器人 |
| AppSecret | 官方模式密钥（加密入库） | 空 | 同上 |
| 开放平台 API 地址 | 官方 REST 根地址 | `https://api.sgroup.qq.com` | 一般不改（沙箱环境才改） |
| AccessToken 服务地址 | 取 token 的地址 | `https://bots.qq.com/app/getAppAccessToken` | 一般不改 |
| NapCat 正向 WebSocket 地址 | 连 NapCat 的 WS 服务端 | 空 | 用正向 WS 时填 |
| NapCat 反向 WebSocket 监听端口 | 插件监听、NapCat 连入 | `3001`（0 = 不启用） | 用反向 WS 或端口冲突时 |
| NapCat access token | 与 NapCat 配置一致（加密入库） | 空（不校验） | NapCat 配了 token 时 |
| NapCat 运行形态 | 无头（Shell）/ 有头（Framework） | 无头 | 想看到完整 QQ 界面时选有头（需 Framework 包） |
| NapCat 启动文件路径 | 一键启动入口 | 空 | 用「启动 NapCat」时必填 |
| NapCat 工作目录 | 可选，留空 = 启动文件所在目录 | 空 | 需要指定时 |
| 登录方式 | 扫码 / QQ 号快速登录 | 扫码 | 本机登录过 QQ、想跳过扫码时 |
| 快速登录 QQ 号 | 作为启动参数传入 | 空 | 选快速登录时填 |
| 启动后自动后台启动 NapCat | 由插件托管 NapCat 进程 | 关 | 想让 ClassIsland 一起拉起 NapCat |
| 启动前结束正在运行的 QQ | 保证 QQ 实例独占 | **开** | 明确知道自己要接管 QQ 进程时才关 |
| 启动后自动打开 WebUI | 打开登录 / 管理页 | 关 | 需要扫码登录时打开 |
| 群白名单 | 接管哪些群；留空 = 接收全部已接入群（不是「不接管」） | 空 | 生产使用建议只填班级群（官方 = 群 OpenID；NapCat = 群号） |
| 作业「整理并发送」 | 显示发送入口并允许发送 | 开 | 不想让插件发群消息时关 |
| 「整理并发送」自动补序号 | 清单每条加 `1. 2. 3. …` | 开 | 想自己排版时关 |
| 作业清单发送目标群 | 清单发到哪些群，与白名单**互相独立** | 空 | 需要发清单时填（官方 = 群 OpenID；NapCat = 纯数字群号） |
| 断线重连参数 | 首次延迟 / 倍增系数 / 延迟上限 | `2` 秒 / `2.0` / `300` 秒 | 网络不稳时调大上限 |

> 注：设置页上「作业『整理并发送』」的说明文字写的是「仅 QQ 官方机器人模式可用」，但代码里 NapCat 模式同样支持发送——走 OneBot 的 `send_group_msg`，因此 NapCat 模式下「作业清单发送目标群」必须填**纯数字群号**（填群 OpenID 会被校验拒绝并提示改填群号）。

### 6.2 CyberTechRep 分类

| 设置项 | 作用 | 默认值 | 什么时候改 |
| --- | --- | --- | --- |
| 启用人工确认队列 | 学科识别不可靠时进队列等人工点选 | 开 | 不想被人工确认打断时关 |

关键词（通知 / 作业）与学科词表都在「CyberTechRep 词表编辑」页，不在本页。

### 6.3 CyberTechRep 词表编辑

| 设置项 | 作用 | 默认值 | 什么时候改 |
| --- | --- | --- | --- |
| 学科关键词规则 | 学科名 + 关键词（一行一个）+ 优先级；学科名同时是文件夹名 | 内置词表 + `Assets/subjects.json` 种子 | 学校叫法和内置词表不一致时 |
| 通知关键词 | 命中次数参与通知侧计数 | `通知、注意、提醒、广播` | 班级常用词不同时 |
| 作业关键词 | 命中次数参与作业侧计数 | `作业、练习、提交、完成` | 同上 |

## 7. 数据与隐私

**数据目录**：默认 `%LOCALAPPDATA%\ClassIsland\Plugins\classisland.classing\data`；实际路径以「设置 → CyberTechRep 关于」页显示为准，该页有「打开数据目录」按钮（目录不存在时会先创建）。

**落盘文件**（都在数据目录下）：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 全部设置（含加密后的密钥）。写入用临时文件 + 覆盖替换，遇文件占用会重试到 3 秒；损坏 / 版本不符时会先改名备份为 `settings.json.corrupt-<时间戳>` 再回退默认值 |
| `notices.json` | 通知条目（含已读状态与时间） |
| `homework.json` | 作业条目 + **学科文档**（同一文件里的 `items` 与 `documents` 两个字段） |
| `files.json` | 文件归档记录（含 MD5、归档相对路径、状态） |
| `message-kind-overrides.json` | 通知 / 作业互转的覆盖记录 |
| `member-subject-bindings.json` | 成员学科显式绑定 |
| `user-subjects.json` | 由人工修正「学」出来的发送者 → 学科映射 |
| `pending-confirm.json` | 人工确认队列（学科识别低置信） |
| `napcat-resume-cursor.json` | NapCat 断点续传游标（每群已入档到哪条） |
| `retry-queue.json` | 失败重试队列 |
| `seen-message-ids.json` | 幂等去重记录 |
| `subjects.json` | 学科关键词词表（可从设置页编辑，缺失时用内置种子重建） |
| `classification-keywords.json` | 通知 / 作业关键词表 |
| `下载文件\`（默认下载根目录，可在「文件」页改） | 归档文件：`学科\yyyy-MM-dd\文件名`；下载中的半成品是本目录下的 `.tmp` 临时文件 |
| `overlays.json.migrated` | 旧版独立悬浮窗设置，已并入 `settings.json` 后归档 |

各 JSON 存储都带 `.bak` 备份（主文件损坏时自动从 `.bak` 恢复，无有效备份则转存 `.corrupt` 后以空数据继续）。注意：**没有独立的 `homework-documents.json`**，学科文档存在 `homework.json` 里。

**密钥保护**：AppSecret、NapCat access token、云端 API Key 都用 Windows DPAPI（`System.Security.Cryptography.ProtectedData`）按本机用户加密后存储，界面不明文回显，不进日志。「导出设置」会把密钥字段置空；「从剪贴板导入设置」不会覆盖本机已保存的密钥。

**是否外传**：

- 消息、文件、通知、作业、学科绑定等默认全部在本机处理，只与你自己配置的消息源通信（QQ 官方平台，或你本机的 NapCat）。
- AI 是可选能力：**只有**你在「CyberTechRep AI」页配好接口并让某个用途用上 AI 时，插件才会把**消息文本**发给你所配置的云端服务（OpenAI 兼容接口或 Anthropic 接口），由该服务返回学科判定。不配置就不会有任何 AI 请求。
- 插件启动后会调用一次 GitHub Releases API（`api.github.com`，默认仓库 `lukeyancn/CyberTechRep`）检查是否有新版本，只发送版本查询请求，不带任何本机数据；检测到新版本会写入一条通知。
- 「导出消息记录」写出的 JSONL 不含任何密钥。

**保留期与清理**：清理任务在插件启动、每日跨天、设置变更时执行。通知保留天数默认 0（永久，不清理）；设为 N 天后，**已读**通知只保留当天，**未读**通知不受限制全部保留。作业保留天数默认 0；设为 N 天则保留最近 N 天（含当天），过期的条目与对应学科文档一起删除。文件按「最多占用磁盘空间」与「达到上限后怎么办」处理：停止接收新文件并提示，或自动删最早的文件。归档文件本身不随通知 / 作业保留期自动删除。

### 8.3 一条群消息的处理路径

1. **接入**：官方 WS 网关或 NapCat WS 收到事件 → 规范化为 `MessageRecord`（文本 / 图片 / 文件 / 视频 / 语音 / @ 段）。
2. **时间口径**：`ReceivedAt` 取协议端时间戳（NapCat 的 Unix 秒 / 官方平台的 RFC3339），缺失、非法或明显越界时回落到本机接收时间。
3. **过滤**：按 `MessageId` 幂等去重（`seen-message-ids.json`）；群白名单非空时只收白名单内的群；NapCat 模式下同时推进断点续传游标。
4. **二分类**：关键词计数 → 通知 / 作业；未命中且文本非空 → 通知；无文本或纯媒体 → 不落通知条目（走文件管道）。
5. **学科**：作业走学科识别链（成员绑定优先 → 关键词 → AI → 人工确认），得到学科与置信度。
6. **落档**：通知写 `notices.json`；作业写 `homework.json` 的条目与对应学科文档；附件交给文件管道下载并归档到 `下载文件/学科/日期/`。
7. **展示**：通知 / 作业悬浮窗刷新；文件归档后学科圆圈点亮红点、图片进图片悬浮窗。
8. **容错**：任一环节失败只记日志并把可重试操作（下载 / 学科识别 / 写入）投进重试队列，按退避重试，也可在排错面板手动重放。

### 8.4 关键设计取舍

| 取舍 | 原因 |
| --- | --- |
| JSON 原子写入 + `.bak` 恢复 | 崩溃 / 断电不产生半截文件；主文件损坏能自愈，最坏情况保留 `.corrupt` 供人工恢复 |
| 按消息 id 幂等 | 协议端重发、断线续传重放都不会产生重复通知 / 作业 |
| 悬浮窗设置单一来源 | 六窗几何与层级统一存 `settings.json`；旧版独立 `overlays.json` 一次性导入后归档 |
| 设置热生效 | 各服务通过委托读取设置快照，保存后广播 `SettingsChanged` 立即生效；`AppId` / `ApiBase` / `TokenApiUrl` 变更会自动重连，接入模式切换与 `AppSecret` 变更需要手动重连或重启（DPAPI 密文每次保存都不同，不参与重连判定） |
| UI 线程约束 | 窗口与位图操作统一经 `Dispatcher.UIThread` 调度，事件源在后台线程也不越界 |
| 打包与部署都剥离宿主程序集 | `Microsoft.Extensions.*`、`System.IO.Pipelines` 由宿主提供，打进包会与宿主产生同名不同源类型，导致插件加载失败 |
| 本地 ONNX 只留骨架 | 推理需要模型与运行时依赖，当前为占位实现（`IsAvailable` 检查模型文件存在，`ClassifyAsync` 返回 null 交给下一级），设置页不暴露 |

## 9. 开发者指南

### 9.1 环境

- Windows + .NET 8 SDK。
- 打包步骤需要 `pwsh`：`ClassIsland.PluginSdk` 的 targets 会调用 `generate-md5.ps1` 生成 `checksums.md`。本机没有全局 `pwsh` 时，把仓库的 `tools/shim` 加进 `PATH` 即可（垫片把 `pwsh` 转发给 `powershell.exe`）。
- 本开发工作区没有安装全局 .NET SDK，用的是随工作区下载的 `dotnet-sdk\dotnet.exe`；该目录在 `.gitignore` 内，不属于仓库内容，克隆后需自备 SDK。

### 9.2 构建 / 测试 / 打包

```powershell
cd <仓库根>
$env:PATH = "$PWD\tools\shim;$env:PATH"    # 无全局 pwsh 时（打包步骤要调 pwsh）

# 本地调试构建
dotnet build CyberTechRep.sln

# 全量测试（Debug）
dotnet test CyberTechRep.sln -c Debug

# Release 构建：产出插件包 src/CyberTechRep.Plugin/cipx/CyberTechRep.Plugin.cipx 与 checksums.md
dotnet build CyberTechRep.sln -c Release
```

（若用工作区自带的 SDK，把上面的 `dotnet` 换成 `.\dotnet-sdk\dotnet.exe`。）

注意事项：

- `CreateCipx` 对**所有配置**生效，且 `dotnet test` 会以 Debug 重新构建插件工程——所以**不要**在 Release 构建之后跑测试，否则 `cipx/` 会被 Debug 包覆盖。CI 里也是先跑测试、再跑 Release 构建，原因见 `.github/workflows/ci.yml` 的注释。
- 测试工程用 xUnit，悬浮窗相关用例跑在 Avalonia Headless + Skia 上（`tests/CyberTechRep.Tests`）。
- 最近一次交付记录：Release 构建 0 错误，全量测试 953 通过 / 0 失败（见 `docs/delivery/2.2.0.0-交付说明.md`）。测试数量随改动增长，以本地实际运行结果为准。

### 9.3 本地部署调试

`tools/deploy-plugin.ps1` 把 Release 产物复制进宿主插件目录，适合边改边调：

```powershell
pwsh -File tools/deploy-plugin.ps1
```

它做的事：等 `ClassIsland.Desktop` 退出（默认最多 1800 秒，宿主加载插件 DLL 后文件会被锁住，无法原地覆盖）→ `robocopy` 把 `src/CyberTechRep.Plugin/bin/Release/net8.0` 覆盖到宿主的 `data/Plugins/classisland.classing`（排除宿主已提供的程序集）→ 校验部署后的 DLL SHA256 与构建产物一致。默认目标目录可用 `-Target` 覆盖。

### 9.4 发布

- 推送 `v*` 标签触发 CI：`windows-latest` 上还原 → **先** `dotnet test -c Debug` → **再** `dotnet build -c Release --no-restore` → 用 `pwsh` 校验 `checksums.md` 里记录的 MD5 与实际包一致 → 上传构建产物 → 标签带 prerelease 后缀（如 `-beta.1`）时自动标记为预发布，并把 `.cipx` 与 `checksums.md` 作为 Release 附件。
- 版本号在 `src/CyberTechRep.Plugin/CyberTechRep.Plugin.csproj`（`Version` / `AssemblyVersion` / `FileVersion`）与 `src/CyberTechRep.Plugin/manifest.yml` 两处，必须同步修改；tag 名通常与版本号一致（CI 不校验两者是否相等，但 Release 会按 tag 生成，建议保持一致）。

### 9.5 代码与测试约定

- 全部公开与内部成员写简体中文 XML 文档注释，说明「为什么这么做」以及边界条件；结论性常量集中定义并配单元测试。
- 目录按职责分层（模块划分见第 8 章），共享模型与接口放 `src/CyberTechRep.Shared`，插件不放入口逻辑。
- 测试文件命名为 `<被测模块>Tests.cs`，测试方法用中文名描述行为；插件工程通过 `InternalsVisibleTo` 向测试工程开放内部成员。
- 新增设置项时：改 `SettingsModels.cs` 并给默认值 → 在对应设置页加控件 → 需要热生效的接到 `Services/Maintenance/SettingsChangeApplier`。
- 插件打包与部署都会剥离宿主已提供的程序集，新增依赖时要确认它是否由宿主提供，避免类型分裂。
- 目录约定：`src` 插件与共享库、`tests` 测试、`tools` 脚本与自检工具、`docs/delivery` 交付说明、`docs/research` 调研。

## 10. 已知限制与 FAQ

**QQ 官方平台与 NapCat 的能力差异**：官方平台群标识是 OpenID（不是群号）、没有历史补拉、不下发撤回事件，且主动消息受频控（代码注释记载：未认证 30 条/分钟、认证后 60 条/分钟，单群每日上限 1000 条；「整理并发送」按主动消息发送）。NapCat 走 OneBot 11，支持历史补拉、撤回上报与群文件 URL 获取，群标识是数字群号，但需要你自己维护 NapCat 与 QQ 客户端。

**撤回**：NapCat 模式下，协议端上报的撤回会联动删除对应通知 / 作业（含学科文档条目，已归档文件不删），默认开启。已知缺陷：**非 API 方式撤回（例如在手机 QQ 上撤回）NapCat 不上报**（上游 issue #1171），这些消息不会被自动删除。可用 `RecallReconcileEnabled`（默认关闭，需手动改 `settings.json`）开启定期核对兜底；该核对用 `get_msg` 探测，消息超期后探测也会失败，存在误判风险，所以默认不开。

**消息时间口径**：通知、作业、学科文档与附件记录的时间都取**消息在群里的发送时间**（NapCat 的 `time`、官方平台的 `timestamp`）；协议端未提供、格式非法或明显越界时回落到本机接收时间。跨天归属也按该时间分桶。同一条消息重投不会刷新已落档的时间。

**图片悬浮窗最多 20 张**：超出后丢弃最旧一张，保留最近收到的；同一文件记录重复到达会被忽略。圆圈红点只在本次运行内有效，重启后历史文件不点亮。

**AI 是可选能力**：需要自备云端 API Key；不配置时所有 AI 环节自动跳过，退回关键词识别，不会报错也不会阻塞消息处理。本地 ONNX 模型目前是**占位实现**（不实际推理），插件实际可用的 AI 只有云端接口。

**安全与操作提示**：

- 「鼠标穿透」只在「固定」开启时生效；同时开启后悬浮窗收不到鼠标事件，拖放导入也会失效。
- 「置顶」关闭时悬浮窗贴在桌面层最底（会被其它窗口挡住，但按 Win+D 显示桌面不会消失）；想让老师随时看到就开置顶。
- 「固定」会禁用拖动与缩放，位置只能回设置页改。
- 群白名单留空的含义是**接收全部已接入的群**（插件会记一条告警日志），不是「不接管任何群」。
- 切换接入模式、改 AppID / API 地址后，需要到「维护与排错」点一次「手动重连」或重启 ClassIsland；群白名单是即时生效的。
- NapCat「有头」与「无头」由发行包决定，两种包不要共用目录。

**其它限制**（来自交付说明记录）：学科文件缩略图在 UI 线程解码，某学科图片很多时首次打开可能有可感知停顿；上课联动「推迟」的等待只在内存里，宿主重启会丢失这一次等待；不同电脑上的真实课表时序未做实测。
