# 插件可行性调研结论

> 项目：ClassIsland QQ 群消息接管与课堂信息分发系统（ClassIng）
> 模块：模块 0 —— 调研与总体设计
> 调研对象：ClassIsland master 分支（克隆自 https://github.com/ClassIsland/ClassIsland ，2026-09-03 快照）
> 说明：本结论基于对仓库源码的直接阅读，所有引用的文件路径均可在本地 `D:\!Mine\plays\ClassIng\ClassIsland` 中找到。

## 1. 关键背景：master 分支的 UI 框架已迁移到 Avalonia

对 master 源码的核实结果（这一点直接影响本项目全部 UI 技术选型）：

| 事项 | 核实结果 |
| --- | --- |
| 目标框架 | `net8.0`（`ClassIsland.csproj`、`ClassIsland.Core.csproj`、示例插件 csproj 均为 `net8.0`，**不是** `net8.0-windows`） |
| UI 框架 | **Avalonia 11.3.17**（`AvaloniaShared.props` 定义 `AvaloniaVersion`；`ClassIsland.csproj` 中 `UseWPF=false`；视图文件为 `.axaml`） |
| 插件 SDK | `ClassIsland.PluginSdk`（NuGet 包形式分发，示例插件以 `PackageReference` 引用并 `ExcludeAssets=runtime`） |
| 插件 API 版本 | manifest 中 `apiVersion: 2.0.0.0`，加载器要求 `apiVersion >= 2.0.0.0`（`ClassIsland/Services/PluginService.cs` 第 168 行附近） |
| 构建要求 | `global.json` 指定 .NET SDK `9.0.100`（rollForward: latestFeature） |

**含义**：网上的 ClassIsland 1.x 插件教程（基于 WPF + MaterialDesign）对 master 已不适用。本项目若以 master 为目标，悬浮窗、设置页 UI 均须用 **Avalonia** 实现，而非 WPF。

## 2. 插件体系如何工作（源码核实）

### 2.1 插件项目模板 / csproj 写法

以仓库内 `ClassIsland.ExamplePlugin/ClassIsland.ExamplePlugin.csproj` 为准：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <EnableDynamicLoading>true</EnableDynamicLoading>   <!-- 关键：插件以可动态加载的程序集构建 -->
    <CreateCipx>true</CreateCipx>                        <!-- 构建时产出 .cipx 插件包 -->
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="ClassIsland.PluginSdk" Version="2.0.0.*">
      <ExcludeAssets>runtime; native</ExcludeAssets>     <!-- 关键：SDK 只用于编译期，不随包分发 -->
    </PackageReference>
  </ItemGroup>
  <ItemGroup>
    <None Update="manifest.yml"><CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory></None>
    <None Update="icon.png"><CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory></None>
    <None Update="README.md"><CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory></None>
  </ItemGroup>
</Project>
```

要点：
- `EnableDynamicLoading=true` + PluginSdk 包 `ExcludeAssets=runtime`：插件依赖（含 ClassIsland.Core）在宿主进程中已存在，不重复分发。
- `CreateCipx=true` 由 `ClassIsland.PluginSdk.targets` 驱动，构建产出 `.cipx`（内含 `manifest.yml`、入口程序集、图标等），即插件安装包格式（`PluginService.cs` 安装逻辑按 zip 包内 `manifest.yml` 识别）。

### 2.2 插件清单 manifest.yml

```yaml
id: classisland.example        # 全局唯一插件 ID（决定安装目录名）
name: 示例插件
description: 插件描述
entranceAssembly: "ClassIsland.ExamplePlugin.dll"   # 入口程序集
url: https://github.com/ClassIsland/ClassIsland
apiVersion: 2.0.0.0            # 必须 >= 2.0.0.0，否则加载失败
version: 2.0.0.0
author: ClassIsland
```

加载流程（`ClassIsland/Services/PluginService.cs`）：扫描插件根目录下以插件 `id` 命名的文件夹 → 反序列化 `manifest.yml` → 校验 `apiVersion` → 加载 `entranceAssembly` → 反射查找带 `[PluginEntrance]` 特性的 `PluginBase` 子类并实例化。

### 2.3 IPlugin 入口（PluginBase）

master 中插件入口基类为 `ClassIsland.Core.Abstractions.PluginBase`（源码 `ClassIsland.Core/Abstractions/PluginBase.cs`）：

```csharp
[PluginEntrance]
public class Plugin : PluginBase
{
    public override void Initialize(HostBuilderContext context, IServiceCollection services)
    {
        // 在宿主 Generic Host 的 DI 容器中注册服务、注册设置页、注册通知提供者等
    }
}
```

可用成员：
- `PluginConfigFolder`：宿主为插件分配的独立配置目录（可直接放本项目自己的 JSON 配置/数据文件）；
- `PluginInfo Info`：manifest 解析结果。

### 2.4 注册服务与设置页

在 `Initialize` 中通过 `IServiceCollection` 扩展注册（均位于 `ClassIsland.Core/Extensions/Registry/`）：

| 扩展方法 | 用途 | 前置要求 |
| --- | --- | --- |
| `services.AddSingleton<T>()` 等常规 DI 注册 | 注册消息接入、分类、存储等自定义服务 | 无 |
| `services.AddSettingsPage<TPage>()` | 在设置窗口注册设置页 | 页面继承 `SettingsPageBase`（Avalonia `UserControl`），类上标注 `[SettingsPageInfo("guid", "页面名", "图标表达式")]` |
| `services.AddSettingsPageGroup(...)` | 新建设置页分组 | 可选 |
| `services.AddNotificationProvider<TProvider>()` | 注册通知提供者（可发起 ClassIsland 全屏/窗口通知） | 类继承 `NotificationProviderBase`，标注 `[NotificationProviderInfo("guid", "名称", "描述")]`，通道用 `[NotificationChannelInfo]` |
| `services.AddRule(...)` / `AddTrigger` / `AddAction` | 注册规则、自动化触发器/动作 | 可选 |

通知能力（`NotificationProviderBase`）：插件可以复用 ClassIsland 的通知宿主（`ShowNotification(NotificationRequest)`），在上课/作业到达时用系统级通知弹窗，这与本项目的"通知悬浮窗"互补（详见架构说明）。

### 2.5 能否添加自定义悬浮窗 / 托盘入口

- **自定义悬浮窗：可行。** 插件是宿主进程内的普通 .NET 程序集，可在 `Initialize` 后（或通过托管的 `IHostedService`/首次使用时）创建自己的 Avalonia `Window`（如 `SystemDecorations="None"` + `Topmost` + 透明背景），ClassIsland 不禁止插件创建独立窗口；仓库内亦有 `MyWindow`、`SplashWindowBase` 等窗口基类可供样式对齐。唯一约束是窗口必须跑在宿主的 Avalonia UI 线程（通过 `Dispatcher.UIThread` 调度）。
- **托盘入口：可行。** `ITaskBarIconService`（`ClassIsland.Core/Abstractions/Services/ITaskBarIconService.cs`）公开了 `MainTaskBarIcon`（Avalonia `TrayIcon`）与 `MoreOptionsMenuItems`（`IList<NativeMenuItemBase>`），插件从 DI 取得该服务即可向主程序托盘"更多选项"菜单追加菜单项（如"打开作业面板""重连 QQ 接入"）。

### 2.6 设置持久化框架现状

- 主程序设置集中在 `Settings.json`（System.Text.Json，`ClassIsland/Services/SettingsService.cs`），主程序没有名为 `SettingsProvider<T>` 的可复用组件；插件生态的通行做法是插件自行在 `PluginConfigFolder` 内读写 JSON 配置。
- 结论：本项目自建 `ClassIngAppSettings`（五组：连接/分类/悬浮窗/文件/维护），用 System.Text.Json 序列化到 `PluginConfigFolder`，与宿主风格一致，不依赖宿主内部类型。

## 4. 结论与风险点

### 结论：以插件形式接入 ClassIsland master **可行**，这是首选方案。

- ClassIsland 2.x 插件体系提供完整的入口、DI 注册、设置页、通知宿主、托盘菜单扩展点，能覆盖"两个悬浮窗 + 设置页 + 通知"的全部宿主侧需求；
- 插件包（.cipx）与插件目录（`PluginConfigFolder`）为部署与数据隔离提供了现成机制；
- 相比修改 ClassIsland 源码（fork 维护成本高、随上游更新冲突），插件形态可以独立迭代。

### 风险点与对策

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| master 为开发分支，Avalonia 迁移中，API 可能变动 | `apiVersion` 校验、`ClassIsland.Core` 接口仍在演进 | 契约层（`ClassIng.Shared`）与宿主 API 隔离；升级时仅适配插件外壳层 |
| 插件 SDK 以 NuGet 预发布/滚动版本（`2.0.0.*`）发布 | 编译依赖浮动 | 锁定具体版本号；CI 中固定日期快照 |
| 悬浮窗需在宿主 UI 线程创建 | 跨线程异常 | 统一经 `Dispatcher.UIThread` 调度，封装进 `ISuspensionWindowController` 实现 |
| GPL-3.0 传染 | 分发合规 | 项目以 GPL-3.0 发布；源码公开 |
| QQ 协议端账号风控 | NapCat 等非官方协议存在封号风险 | 文档明示风险；默认建议使用小号；协议端独立部署、可随时停用 |
| 官方"插件开发文档"相对滞后于 master 源码 | 文档描述可能仍是 1.x WPF | 以仓库源码（示例插件 + Core 扩展方法）为准，本文档已按源码核实 |
