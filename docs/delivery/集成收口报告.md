### 2.3 重试执行器（任务 3）

经 `RetryQueueService.RegisterExecutor` 注册三个真实执行器（payload JSON 与 RetryQueueService 序列化命名策略一致）：

- **FileDownload**：重调 `IFilePipelineService.EnqueueAsync`；返回 Archived/Duplicate 视为成功；载荷不可解析（JSON 异常）视为作废记成功防无限退避，缺 Url/管道未注册按失败退避；
- **SubjectClassify**：重调学科链 → 重写 HomeworkStore；`NeedsManualConfirm=false` 才算成功（仍需人工确认则继续退避，人工队列投递由链内幂等）；
- **StoreWrite**（补齐模块 8 预留的 `StoreWriteCallback` 透传点）：按载荷种类重放 通知写入 / 作业写入（含学科链重识别）/ 作业学科写回。

接线层任何一步失败：try/catch + 结构化日志 + 按类型投递重试队列（`EnqueueRetrySafeAsync` 保证入队本身失败也不抛出），**任何一环失败不崩溃、不向事件源传播异常**。

### 2.4 悬浮窗设置迁移（任务 4）

`SuspensionWindowController` 原先独立读写 `dataDir/overlays.json`，与模块 7 `ISettingsService.Overlays` 双源并存（模块 5 报告缺口）。本次：

- 控制器新增可选 `ISettingsService` 注入（`Plugin.cs` 已传入，旧 3 参构造保持兼容供既有测试使用）；

## 五、剩余风险

1. **文件二次归档失败仅记日志**：`ReassignSubjectAsync` 失败（如文件被占用）为幂等操作、不进重试队列（语义上非 FileDownload/SubjectClassify/StoreWrite 任一类型），依赖后续人工 Resolve 或下次识别再次触发；风险低但非自动重试。
2. **附件直链时效**：官方平台附件 URL 带签名有时效；FileDownload 重试在链接过期后必然失败至 GivenUp，需上游换新链接重新入队（模块 4 报告已声明的平台限制）。
3. **重试载荷作废策略**：重试 payload JSON 损坏时按「作废记成功」处理（日志留痕），避免无限退避；极端情况下该条操作不会真正执行。
4. **设置回环防护依赖实例同一性**：悬浮窗设置回写防死循环依赖 `OverlayWindowSettings` 引用比较；若未来有人复制实例后传入广播链，可能出现一次冗余保存（非死循环，仅多一次写盘）。
5. **全解决方案历史警告 382 条（既有基线）**：主要为 CA1416 与设置页 XAML 警告，属模块 6/7/8 遗留，建议后续单独清理（本次按纪律未动）。
6. **SuspensionWindowControllerTests 偶发非稳定失败**（并行测试下模块 6 已报告的历史现象，与本次改动无关）：本次多次全量回归均全绿。
